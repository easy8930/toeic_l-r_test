# Listening Room

お子さんの音声学習向けの、ログイン不要の静的Webアプリです。GitHubで管理者が用意した教材音声だけを表示・再生します。公開画面にはファイル選択、音声取り込み、音声の追加・削除、番号変更、まとめの追加・削除、記録のインポート機能はありません。

## 起動・ビルド

Node.js 22以上。

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
npm run preview
```

`npm run dev` はポート5173、previewは4173。起動・ビルド前に音声を準備します。ビルド結果は `dist/`。サーバーへの書き込みAPI、ユーザー認証、共有の学習記録データベースはありません。

## 音声の登録：管理者がGitHubまたは作業フォルダーで操作

1. `audio-source/` に番号付きのMP3などの音声ファイルを追加します。ZIPも利用できますが、GitHubのWeb画面からアップロードできるファイルは1ファイル25MiBまでのため、大きなZIPはパソコンで解凍して個別のMP3を登録してください。
2. `npm ci`、`npm run build` を実行するビルド環境で `public/audio/manifest.json` と音声ファイルを自動生成します。個別に実行する場合は `npm run bundle-audio`。
3. 生成した `dist/` を静的ホスティングに配置します。GitHubに音声を追加しただけでは、ビルド・公開設定がないサイトには自動反映されません。この作業ではデプロイを実施していません。

ZIPと、そのZIPを解凍した音声を重ねて配置しないでください。同じ番号・判別不能な番号はエラーにします。ファイル名の最後の4桁以下の数字をトラック番号として使用します。番号を訂正する場合は管理者が元ファイルを変更して再ビルドします。

音声は内容のハッシュを含むURLで配信し、再生する時点で読み込みます。端末ごとの取り込みは不要です。同じ番号の再生回数は再ビルド後も維持します。旧バージョンでブラウザに取り込んだ音声は公開一覧を上書きしません。同梱一覧にある番号について再生回数のみ引き継ぎます。旧ブラウザ保存データは消去しませんが、旧音声の再生には利用しません。

`audio-source/` はGitに追加できる設定です。`public/audio/`、`dist/`、`node_modules/` はGit対象外です。現在のリポジトリに実教材音声は含まれていません。添付の音声ZIPは実行環境の32MiB転送上限で取得できなかったため、管理者の配置が必要です。

## 学習機能

- 音声一覧と右側の再生完了回数
- 指定した番号範囲、または教材で確認できたグループの連続再生
- 範囲のリピート、速度変更、シーク、前後への移動
- 大きな操作画面、対応環境でのMedia Session・Wake Lock
- 学習記録のJSON書き出し（読み込み機能なし）

再生が最後に到達すると1回加算します。一時停止・再開では増えません。シークで終端へ進んだ場合も1回加算します。途中で次へ進めたトラックは加算しません。

## 記録と公開の範囲

学習記録・再生設定は端末ごとのlocalStorageに保存し、サーバーに送信しません。別の利用者の端末で再生しても、お子さんの端末の回数には影響しません。端末間同期はありません。同じ端末・同じブラウザを別の人が使う場合は、同じ記録になります。ブラウザのデータ削除・プライベートブラウズ・保存領域の削除で記録が失われる場合があります。

公開サイトはURLを知る誰でも閲覧・再生できます。アップロード用UIや書き込みAPIがなくても、閲覧者を本人だけに制限するものではありません。ブラウザ内の画面や自分自身の記録を閲覧者が改変することも防げません。GitHubのファイル変更権限はGitHub側のリポジトリ権限で管理します。

教材音声を公開リポジトリや一般公開サイトに置くと、第三者も取得できます。提供元の利用条件と公開・再配布の可否を確認してください。家族だけで利用する目的なら、自宅LANでの運用、VPNによる限定接続、またはホスティング側のアクセス制限を検討できます。非公開リポジトリだけでは、一般公開サイトの閲覧は制限されません。

## 同じWi-Fiでスマートフォンから開く

1. パソコンとスマートフォンを同じWi-Fiにつなぎます。
2. パソコンで `npm run dev` を起動したままにします。
3. Windowsの `ipconfig` でWi-FiアダプターのIPv4アドレスを確認します。
4. スマートフォンで `http://パソコンのIPv4アドレス:5173/` を開きます。localhostは使いません。起動時に別ポートが表示された場合はその番号を指定します。

Windowsの確認が出た場合は、信頼するプライベートネットワークでNode.jsを許可します。ファイアウォールの無効化やルーターのポート開放は不要です。ゲストWi-Fiの端末間通信制限で接続できない場合があります。アドレス・ポートが変わると別の保存領域になります。

スマホの背景・画面ロック中の再生は端末とブラウザに依存します。実機検証は未実施です。Wake LockはHTTPS等の対応環境でのみ利用できる追加機能です。

## 検証

`npm test` と `npm run build` を実行します。開発サーバーの起動中に `python3 scripts/bundled_smoke.py` を実行すると、生成WAVを使った取り込み不要の再生、連続再生、範囲終端、再読み込み後の回数、別ブラウザの記録の独立、検索、書き出し、ファイル選択・編集UIがないこと、320/390px表示を確認します。Python Playwrightと `/usr/bin/chromium` が必要です。既存の `public/audio/` がある場合は教材保護のため停止します。実教材を含めた試聴テストではありません。

## GitHub上でビルドしてテストする

GitHub Actionsの **Build Listening Room** が、`main` へのプッシュで自動的に `npm ci` → `npm test` → `npm run build` を実行します。GitHubの **Actions → Build Listening Room → Run workflow** から手動実行もできます。サイトの公開・デプロイは行いません。

成功した実行の下部 **Artifacts → listening-room-dist** からビルド済みZIPをダウンロードできます（GitHubログインが必要な場合があります）。保存期間は7日です。実行サマリーに同梱トラック数が出ます。音声がGitHubの `audio-source/` に未配置なら0件となり、アプリ本体だけをビルドします。

ローカルで成果物を試す場合、ZIPの中の `index.html`・`assets/`・存在する場合は `audio/` を、ソースコードのフォルダー内の `dist/` に展開します。そのフォルダーで `npm ci` と `npm run preview` を実行し、表示されるURLをブラウザで開きます。`index.html` のダブルクリックでは正常動作しません。ビルド成果物には登録済み教材音声も含まれるため、ダウンロード後の扱いも教材の利用条件に従ってください。

## GitHub Pagesでの公開

`.github/workflows/pages.yml` が `main` へのプッシュでテスト・リポジトリURL向けビルド・GitHub Pagesへのデプロイを行います。公開先は `https://easy8930.github.io/toeic_l-r_test/`。GitHub PagesのSourceはGitHub Actionsを使用します。

一般公開のため閲覧・再生にログインは不要です。音声ファイルもサイトから取得可能になります。管理者が `audio-source/` に追加した音声は次回のビルドで公開サイトに反映されます。再生回数は公開サイトを開いた各ブラウザ内だけに保存され、ローカル版の記録とは別になります。
